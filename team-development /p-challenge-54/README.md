# 課題54

**課題１（質問）**

#### アジャイル開発とは何でしょうか？

アジャイル開発とは、従来の「ウォーターフォール開発」とは対照的なソフトウェア開発手法です。その主な特徴は以下の通りです。

- 短いサイクルの反復
  - 1週間から1ヶ月程度の短い期間を設定し、その中で「分析・設計・実装・テスト」という一連の工程を繰り返します。この短いサイクルごとに、実際に動作するソフトウェアの一部を完成させます。
- 早期かつ継続的な提供
  - 動作するソフトウェアを少しずつ、かつ頻繁に提供することで、顧客は早い段階で価値を手にすることができます。
- 変化への柔軟な対応
  - 開発の途中でも顧客やユーザーからのフィードバックを積極的に取り入れ、仕様の変更や優先順位の見直しに柔軟に対応します。
- 価値観の重視
  - 単なる開発手順ではなく、「チームメンバーや顧客との協調とコミュニケーション」「変化を受け入れる柔軟性」「開発者のモチベーション」といった価値観を重視します。これは「プロセスやツールよりも個人との対話を」「包括的なドキュメントよりも動くソフトウェアを」といった思想に表れています。

#### どのような問題を解決するのでしょうか？

アジャイル開発は、従来のウォーターフォール開発で起こりがちだった、以下のような問題を解決します。

- 開発終盤まで成果物が見えない問題
  - ウォーターフォール開発では、最後にしか動くソフトウェアが完成しないため、顧客は開発途中で実際の動きを確認できませんでした。アジャイル開発は、短いサイクルで動くソフトウェアを提供するため、この問題を解決します。
- 仕様の誤解と手戻りの問題
  - 文書中心のやり取りで発生しがちだった仕様の誤解や、開発終盤での大規模な手戻りを、顧客との密なコミュニケーションと頻繁なフィードバックによって防ぎます。
- 市場や要求の変化に対応できない問題
  - 開発期間が長いと、完成した頃にはビジネス環境や顧客の要求が変化していることがありました。アジャイル開発は、短いサイクルでフィードバックを取り入れ、変化に柔軟に対応することで、常に価値の高いソフトウェアを提供し続けることを目指します。

**課題2**

- あなたが現在開発しているサービスのユーザーストーリーを5つ作成してください
- ユーザーストーリーを作成するときは「機能」に言及しすぎないことが大切です
    - 例えば**「私はユーザーとして、ログインすると、自分がアップロードした画像の一覧が見れる」**というユーザーストーリーを作成した場合を考えてみましょう。
    - このユーザーストーリーではログインという機能に関する言及しかないため、ストーリー通りに実装したとしても、画像のURLさえ知っていれば誰でもユーザーがアップロードした画像を見れてしまう可能性があります。
    - ユーザーが本当に満たして欲しいのは「ログイン」という機能でしょうか？それとも「自分がアップロードした画像は自分しか見れない」という関心事でしょうか？
    - 機能に言及しすぎないように注意しながら考え直してみると**「私はユーザーとして、自分がアップロードした画像は、自分以外のユーザーが見れないようにしたい」**と書き換えられるかもしれません。
    - このようにユーザーの関心事や実現したいことをユーザーストーリーとして書き出して、そこから「ログイン画面」や「画像のURLに対するアクセス許可」などの機能をサブタスクとして導出した方が、より機能の見落としが少なくなるかもしれません。もしこの考え方がしっくり来るようでしたら、活用してみてください。
